# 数据集实验

[English](README.md) | 中文

## 摘要

实验脚本通过受支持的 DSH 配置启动应用，保留规范会话，并将模型回答与独立计算的期望值比较。它们生成面向 Fireworks 托管文本 SFT 和单轮 DPO 的本地候选数据，不上传数据，也不证明渲染器兼容性。[实测结果](../../../results/trace-curation-20260908/REPORT.md)包含复杂 UAT 和被拒绝的候选数据。

<a id="run-and-audit"></a>
## 运行与审计

启动批次前先构建插件。`campaign.py <output-directory> <trial-count> <root-workers>` 分配新的 home 和夹具目录；重复调用会分配新的尝试目录。它使用保留的 medium 推理力度发现配置作为模板，并使用端口 4107 上的本地记录代理。此夹具模板和路由使运行器依赖当前部署。每个批次应使用新输出目录；汇总文件描述最近一次调用，各次尝试的证据仍被保留。

运行器提供完整追踪配置，因为 Cordis 配置补丁会替换整个对象。新试验使用稳定项目 `gh-training-live`，并记录实验、任务族、试验和数据划分元数据。最初 240 次试验批次的配置不完整，在 `gh-genai-traces` 中仅捕获元数据；其规范会话仍可用于丰富内容回放。

`prepare-audit.py <campaign-directory>` 准备审计清单和覆盖配置。它根据存储目录名识别会话，不对内容解码。试验使用独立存储时，它将字节复制到审计存储，保留所有格式代次。`audit-profile.ts` 通过 `pnpm dsh --profile headless` 作为覆盖配置加载，经上游 `sessionQuery` 读取各会话、写入独立快照，并调用追踪后端的回放方法。审计清单选择会话，绝不启动录制的代理。所有子会话都必须显式加入；没有独立评分的子会话不进入训练候选数据。

<a id="admission-and-provenance"></a>
## 准入与来源

`./curation` 库验证完整的最终助手回答、支持的文本/推理/工具块、工具定义、JSON 参数对象、唯一工具调用 ID、调用与结果配对、角色位置及损失权重。较早的助手消息权重为零。最终推理保留在源证据中，但不进入正损失目标，因为回答评分不能证明推理质量。图像及不支持的块会被拒绝。

捕获拒绝与任务评分相互独立。截断、省略、脱敏、无法序列化、不完整或未经隐私审核的内容不能进入候选数据。完整捕获的失败回答仍可用于偏好评估，但不进入 SFT。评分器分别报告语法、语义、工具轨迹和环境结果。进程成功退出不能证明其中任何一项。

候选数据保留规范会话/版本/事件标识、源与行哈希、规范化请求/工具/配置哈希、请求的推理力度、任务族、配置标识和评分器版本。缺少检查点、分词器及后端渲染器证据时保持未知。父子关系、任务族和相同请求组成相连的划分组；保留测试集优先于验证集和训练集。完全重复的行保留来源引用，但不计入唯一 SFT 产出。

<a id="preference-sampling"></a>
## 偏好采样

`GH_FROZEN_SAMPLING=1` 在 48 次试验中选择六个确定性题目，每题独立采样八次。显式 `frozen-profile` 覆盖配置在上游记录请求前提供完整文本策略，移除工具与运行时上下文，并设置 medium 推理、温度 0.9 和 2,048 token 输出预算。此独立文本实验禁用仓库指令与技能目录注入，其评估范围小于常规生产代理批次。

记录代理验证各请求组内序列化的提供方请求体完全相同。构造偏好前，整理库还要求规范重建请求完全相同，包括配置和工具。托管 DPO 准入还要求单个用户轮次、无工具、不同且完整的助手输出，以及同一评分器版本下独立判定的一对通过/失败结果。任务相同但请求不同的回答不能配对。

所选后端为 [Fireworks 托管 SFT](https://docs.fireworks.ai/fine-tuning/fine-tuning-models) 和[托管 DPO](https://docs.fireworks.ai/fine-tuning/dpo-fine-tuning)。本地模式测试覆盖保守子集。Fireworks 模型资格、最小数据集大小、注册渲染器、推理历史行为、渲染 token ID 和损失掩码仍需后端验证。两个本地偏好对不满足文档规定的三个样例下限。未创建付费训练任务。

<a id="reward-environments"></a>
## 奖励环境

`GH_REWARD_RESET=1` 在新目录中以相同初始夹具重复写入并读回任务。推理前记录输入哈希，轨迹完成后观察输出状态。`./reward` 库提供私有夹具分配和独立的 JSON/文件完整性奖励。最终回答正确但文件错误或输入被修改时，文件系统奖励为零。负对照测试证明新重置不会继承先前的答案文件。

这些实验提供可重置轨迹和确定性奖励观察，并非 token 级 RFT 训练数据：采样 token ID、对齐的对数概率及已验证的推理/训练分词器关系均缺失。重新分词最终文本不能恢复这些证据。

<a id="provider-evidence"></a>
## 提供方证据

[记录代理](../../../recproxy.py) 通过 `REC_CONCURRENCY` 限制实际转发请求，包括辅助调用和子调用（当前部署设为四）。记录区分准入、排队等待、首批响应字节、状态、完成和客户端写入失败。`REC_RESPONSE_BYTES` 限制保留的响应片段。`metrics.py` 只读抓取引擎指标；运行/等待峰值采样仅为下界，引擎计数器可能包含其他消费者。

`phoenix-export.py` 分页导出跨度，并分别报告执行根和对话模型的延迟分布。回放模型延迟是录制块的时间，不是推理调度延迟。辅助调用始终标记用途。默认不导出独立的初始化事件跨度；未展示的事件仍以规范记录为准。
