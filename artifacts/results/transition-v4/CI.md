# Fork CI configuration

The Issue Policy and Issue Lifecycle jobs require the upstream organization’s GitHub App credentials. The Cloudflare preview deploy requires its hosted project credentials. These three jobs run only when `github.event.repository.fork` is false; fork build, test, packaging, and artifact checks remain enabled.

The fork-artifacts workflow runs on every pull request and supports manual dispatch. It has no path filter because large upstream merges can exceed GitHub’s changed-file evaluation limit; see [workflow diff filtering](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#git-diff-comparisons). The first PR had no fork-artifacts run despite relevant changes; path filtering is a suspected cause, not an observed GitHub diagnostic.

The initial Issue Policy and Issue Lifecycle failures reported a missing GitHub App client ID. The initial Cloudflare preview built successfully and failed at upload because its API token was absent. These failures do not establish a code-test failure. YAML parsing and repository fork status were checked before publishing the conditions; actual job skipping and fork-artifacts execution require the subsequent GitHub run.

Forks use `ubuntu-24.04` and `windows-2025` for the seven jobs that otherwise request upstream’s named 16-core runners. Gate, coverage, lint, publication-check, and Web snapshot worker limits are two on these smaller runners; session snapshot concurrency is four. Upstream runner selection and limits remain intact. The initial queued jobs reported upstream labels with no assigned runner, while standard hosted jobs executed. Validation compared parsed workflows and preserved every job, step, and dependency.

The workflow behavior tests exercise fork and upstream runner selection and upstream-only integration guards. Cache write tests await the writes actually triggered by lifecycle events, assert their invocation counts, and inspect durable records after completion. PowerShell startup retains observed output across silent readiness continuations. The persistent-shell scenario allows its two configured 300-second cold-start deadlines plus 60 seconds for subsequent commands. Native Windows tests use verbose reporting to identify the last completed test if a worker exits unexpectedly; the initial worker crash has not reproduced locally.

The native Windows command records child PID, exit code, and signal through Node's `child_process` diagnostics channel; it does not log child arguments or environment variables. The same PowerShell command passed all 68 tests on Linux, and a child deliberately exiting with code 23 produced that code in the diagnostic. Windows run [34627270143](https://github.com/afezzardi/deepseek-harness/actions/runs/34627270143) predates this exit diagnostic and still reports a Vitest fork exiting unexpectedly; its verbose output alone does not identify the cause.

Fork coverage uses two single-worker instrumented partitions plus one worker for the exempt-heavy gate. The partition count replaces the instrumented share of `DSH_COVERAGE_MAX_WORKERS`; lowering only that worker setting leaves four instrumented processes. Linux coverage in run 34627270143 failed only the six-million-element Python completion memory regression at its 60-second runtime deadline. The fixture and its memory, value-size, and timeout assertions remain unchanged; whether the smaller partition count resolves that timeout requires CI confirmation.

Windows coverage in that run failed only when a catalog scan opened a deleted lint probe. The private-workspace fix passed the lint and catalog suites together (32 tests); restoring the original placement failed the new isolation assertion. The cache and PowerShell failures did not recur. The native diagnostic's first isolated run failed in its launcher because Node requires a file URL for a Windows ESM preload. After correcting that URL, [run 34629629560](https://github.com/afezzardi/deepseek-harness/actions/runs/34629629560) passed 67 native tests with one platform skip. The original worker crash remains unexplained; a passing diagnostic is not proof of a fix. No further full PR matrix was launched for these changes.
