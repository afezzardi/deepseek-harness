# Agent Note: 可执行 lint 探针使用独立工作区

Status: implemented

[English](2026-09-11-private-lint-contract-workspace.md) | 中文

## 问题

可执行 lint 测试会创建临时 TypeScript 源文件，以验证项目发现以及源码与测试的规则差异。并发目录扫描可能先枚举到探针，在其所有者删除文件后再打开它，从而报 ENOENT。唯一文件名能防止写入者之间的冲突，却无法隔离源码树的读取者。

## 决策

[lint 测试](../../../../scripts/oxlint-contract.spec.ts) 将 TypeScript 项目布局复制到独占的临时工作区，以只读方式共享依赖项和原生声明目录，并在同步子进程完成后删除工作区。探针不会进入实际检出目录。每个项目发现探针存在时，断言都会检查这一放置要求。

[运行器临时存储策略](2026-09-06-pr-ci-runner-temporary-storage.zh.md) 继续负责作业清理和容量。本决策增加该存储内的读取隔离，不替代运行器策略。

## 考虑过的替代方案

**目录生成器忽略丢失文件。** 这会掩盖源码变更，并且未解决临时文件的所有权问题。

**仅在一个 Vitest 进程内串行执行测试。** 这无法保护其他覆盖率分区中的扫描。

## 影响

复制工作区会增加初始化 I/O 和临时磁盘占用。目录扫描可以与 lint 探针并发运行，而不会读取探针的临时源文件。
